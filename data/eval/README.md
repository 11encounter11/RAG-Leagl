# 检索评测集

## 这是什么

`legal_qa_eval.jsonl` 是**检索质量**的基准数据集：每条样本给出一个问题，
以及该问题**必须**命中哪些法条。它回答的是"检索这一步对不对"，
不评价回答的文笔 —— 检索错了，后面的生成再漂亮也是基于错误依据。

## 字段说明

| 字段 | 含义 |
|---|---|
| `id` | 样本编号，`L01` 起 |
| `question` | 用户问题原文。口语化写法是刻意的，要能反映真实输入 |
| `kind` | 问题类型，见下表 |
| `answerable` | 在**当前语料**中是否可回答 |
| `law` | **标准答案所属的法**（如 `"中华人民共和国劳动法"`）。可写成数组表示"多部法都算对"。超纲题不填 |
| `required` | 必须命中的条文号。命中记 2 分，缺失则召回不完整 |
| `acceptable` | 可接受的条文号（相邻条款、同类规定）。命中记 1 分 |
| `notes` | 该题在考什么，以及容易搞错的地方 |

### 为什么必须有 `law`（2026-10-14 新增）

原先只标条文号。在语料只有一部法时没歧义，但语料扩到 9 部法后就会**跨法误判**：

| 条文号 | 《劳动法》 | 《劳动合同法》 |
|---|---|---|
| 第三十六条 | 每日工作时间不超过八小时 | 用人单位与劳动者协商一致可解除劳动合同 |

只比条文号的话，第一条问题命中了《劳动合同法》第三十六条也会被判成"答对了"——
**指标虚高，而且不报错**。所以匹配改为「法名 + 条文号」（`metrics.grade_hit`），
自检也改为逐部校验（`corpus_index`，见 `app/core/eval/corpus.py`）。

> 顺带修掉一个更隐蔽的问题：原自检只读 `.txt` / `.md` 语料，
> 语料换成官方 `.docx` 之后它就**什么都没收集到，自检等于空跑**。现在按单元素法定名逐部索引。

### `kind` 取值

| 值 | 含义 | 为什么单独统计 |
|---|---|---|
| `term` | 法条术语问法 | 术语与原文重叠高，是效果上限的参照 |
| `colloquial` | 大白话问法 | 真实用户的主要形态，也是向量检索最容易失手的地方 |
| `compound` | 一问含多件事 | 考多路召回与子问题拆解是否有效 |
| `out_of_scope` | 知识库外的问题 | 正确答案是**拒答**，不是"尽力回答" |
| `validity` | 涉及时效 / 地域 | **P0 目标项**：当前语料无版本与地域元数据，预期不达标，用于量化 P1 的改进 |

## 评分方式

按命中条文的"必需 / 可接受"分档打分，位置越靠前得分越高：

- **Recall@k** —— top-k 里是否至少命中一条相关内容（二值）
- **完整召回@k** —— 复合问题需要多条法条，只中一条不算完整
- **MRR** —— 第一条正确结果出现位置的倒数
- **NDCG@k** —— 反映排序质量：同一条命中，排在前面得分更高

超纲题不参与上述指标，单独统计**拒答准确率**（检索返回空才算通过）。

## 使用

```bash
# 自检: 校验标准答案是否真的在语料里。不依赖任何基础设施, 改完评测集就该跑
python scripts/run_eval.py --check

# 纯检索评测(不含 LLM, 无调用成本)
python scripts/run_eval.py --top-k 5

# Agentic 工作流评测(会调 LLM, 用于对比"改写+重排"到底有没有增益)
python scripts/run_eval.py --top-k 5 --mode agentic
```

报告写入 `data/eval/reports/run-<mode>-<时间戳>.json`，含逐题明细，
可直接定位"哪些问题没命中、实际召回了什么"。

## 维护规则

1. **标准答案必须是语料里真实存在的条文号** —— `--check` 会强制校验。
   按记忆标注是最容易出错也最难发现的：指标会虚低，而原因看起来像是检索不行。
2. **新增样本优先补 `colloquial` 和 `out_of_scope`**：前者是真实用户形态，后者是安全底线。
3. **不要为了好看删掉失败的样本**。失败样本是这张表的价值所在 ——
   `validity` 类那两条现在就是故意留着不通过的。
4. 语料变了（新增法律），要重跑 `--check`，并补上对应领域的样本。

5. **每条样本最终必须带法名**（计划中，见下方「已知缺口」）。当前 `required` 只写条文号，
   语料只有一部法时没歧义；语料扩容到多部法后，`第三十六条` 会在劳动法与劳动合同法里同时存在，
   只按条文号匹配会把命中判错（且不报错）。

## 标准答案复核记录（2026-10-14 提出，2026-10-15 改判）

以下样本当初是在"语料只有《劳动法》"的前提下标注的。语料扩到 7 部法后，它们的
标准答案指向了**过时或不专门**的那一部，必须复核。

改判原则（把两类问题分开，不混在一起谈）：

1. **有唯一正确答案**（新旧规则冲突 / 旧法只有原则性规定）：按现行法改，旧条文不再算对。
   这类是**事实**，可以逐条核对话料原文确认，不需要"拍板"。
2. **多部法都能回答、只是有的更具体**：这不是对错问题，用 `law` 数组 + `acceptable`
   表达成"都算对"。

| 样本 | 问题 | 原标注 | 改判结果 | 依据 |
|---|---|---|---|---|
| **L23** | 申请劳动仲裁有没有时间限制？ | 《劳动法》第八十二条（60 日） | **改为《劳动争议调解仲裁法》第二十七条（1 年）**，旧条**不再**列为可接受 | 新旧规则冲突：《劳动法》第八十二条的"六十日"是 1994 年旧规则，已被 2008 年施行的《劳动争议调解仲裁法》第二十七条取代（新法且专门法优于旧的一般法）。**用 60 日回答用户是错误建议**，所以旧条不能算"部分正确" |
| **L11** | 经济补偿应该怎么给？ | 《劳动法》第二十八条 | **改为《劳动合同法》第四十七条**，第四十六条 / 第五十条列为可接受 | 《劳动法》第二十八条只说"依照国家有关规定给予经济补偿"，不回答"怎么给"；标准（每满一年一个月工资）在《劳动合同法》第四十七条，适用情形在第四十六条 |
| **L21** | 公司一直不给我交社保，我该怎么办？ | 《劳动法》第七十二条 | **改为《社会保险法》第六十三条**，《劳动法》第七十二条等列为可接受；`law` 写成数组 | 用户问"我该怎么办"——直接回答处置路径（责令限期缴纳/补足、可划拨、可申请强制执行）的是《社会保险法》第六十三条；缴费义务本身见《劳动法》第七十二条 |
| **L28** | 受了工伤能享受哪些待遇？ | 《劳动法》第七十三条 | **改为《工伤保险条例》第三十条**，第三十三条 / 第三十五条列为可接受 | 《劳动法》第七十三条只列举"因工伤残或患职业病"属于法定待遇情形，不回答"有哪些待遇"；具体待遇在《工伤保险条例》（第三十条 工伤医疗待遇 / 第三十三条 停工留薪 / 第三十五条 一至四级伤残待遇） |
| L16 | 工作满多久可以享受带薪年休假？ | 《劳动法》第四十五条 | **不改** | 第四十五条正面回答"连续工作一年以上"，已经是对的；《职工带薪年休假条例》第三条给的是天数，属"更具体"而非"更正确"。为控制改动面，本次不动 |
| L12 | 公司三个月没发工资 | 《劳动法》第五十条 | **不改** | 问题没有限定"农民工"，《保障农民工工资支付条例》适用范围对不上；《劳动法》第五十条"工资应当以货币形式按月支付…不得克扣或者无故拖欠"正中问题 |

> **改判只影响"尺子"，不改变系统行为。**
> L23 这条尤其要分清：检索**本来就召回了**《劳动争议调解仲裁法》第二十七条，
> 是标准答案标错才把它判成未命中 —— 改判后它应当由"漏检"变成"命中"。
>
> **实测已验（2026-10-16，`data/eval/reports/run-direct-20261016-162026.json`；重排关口径，历史记录）**：
> Recall@5 0.8056 → **0.8611**、完整召回 0.7222 → **0.8056**、MRR 0.5222 → **0.5778**、
> NDCG 0.5796 → **0.6302**、未命中 7 条 → **5 条**。**L11 / L23 / L28 三条如期由漏检转命中**
> （同一份向量、同一套代码，涨幅全部来自标注改对，不代表检索变好）。
>
> **但 L21 改判后仍未命中**，且原因不是标注：单独探针测得
> 「公司一直不给我交社保，我该怎么办？」这句口语问法下，《社会保险法》第六十三条排候选池
> （30 条）**第 11**；换成法言法语「用人单位不缴纳社会保险费 责令限期缴纳 补缴」后同一条**排第 1**。
> 这是 F2.7「口语化 → 法律要素映射」（P2，未实现）的第一个硬证据。
> **没有为此回改标注** —— 把尺子改弯去迁就检索，等于把问题抹掉。

**L23 暴露的一个系统级缺口（本次未解决）**：《劳动法》2018 修正版**整部法仍是现行有效**，
所以"文件级"的时效过滤**不会**排除它 —— 系统仍可能召回并引用已经被取代的第八十二条（60 日）。
这不是"旧版本被召回"，而是"**条文**被新法取代、但我们的时效管理只到文件级"。
处置方向：给 `law_articles` 加条文级取代关系（`superseded_by` 列或 `article_relations` 表），或在生成侧加"新旧法冲突以新法为准"的规则——两者**都未实现**，见根 README 的 [已知限制](../../README.md#十二已知限制) 第 1 条。
